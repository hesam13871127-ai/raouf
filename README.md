# آموزشگاه فنی و حرفه‌ای رئوف — وب‌سایت کامل

وب‌سایت چندصفحه‌ای، کاملاً فارسی و RTL برای «آموزشگاه فنی و حرفه‌ای رئوف»؛ شامل صفحه اصلی، فهرست دوره‌ها، **چهار صفحه مستقل برای هر دوره**، درباره آموزشگاه، گالری تصاویر، تماس با ما، مشاوره و ثبت‌نام و صفحه ۴۰۴.

طراحی بر اساس لوگو، پوستر رسمی و تابلوی آموزشگاه و با پالت رسمی سرمه‌ای / آبی / کرم / بنفش / یاسی انجام شده است. لوگوی اصلی بدون هیچ تغییری (حتی بدون تبدیل فرمت) کپی و استفاده شده است.

---

## ۱. اجرا و نصب

پیش‌نیاز: **Node.js نسخه ۱۸ یا بالاتر**. پروژه هیچ وابستگی زمان اجرا (runtime dependency) ندارد؛ نیازی به `npm install` برای اجرای سایت نیست.

```bash
cd raouf
npm run build      # ساخت ۱۱ سند HTML استاتیک + robots.txt + sitemap.xml
npm start          # اجرای سرور روی http://localhost:3000
```

یا در یک دستور:

```bash
npm run dev
```

متغیرهای محیطی:

| متغیر | پیش‌فرض | توضیح |
| --- | --- | --- |
| `PORT` | `3000` | پورت سرور |
| `HOST` | `0.0.0.0` | آدرس اتصال (برای پیش‌نمایش/دیپلوی روی `0.0.0.0` بماند) |
| `SITE_URL` | `http://localhost:3000` | **قبل از build در محیط production تنظیم شود** تا `sitemap.xml` و نشانی‌های Open Graph مطلق و صحیح باشند. مثال: `SITE_URL=https://example.ir npm run build`. سرور Node علاوه بر آن، `sitemap.xml` و `robots.txt` را به‌صورت پویا با میزبان واقعی درخواست تولید می‌کند |
| `DATA_DIR` | `<ریشه>/data` | محل ذخیره درخواست‌های فرم |
| `ADMIN_TOKEN` | خالی | با تنظیم آن، endpoint ادمین فعال می‌شود |
| `ADMIN_WEBHOOK_URL` | خالی | در صورت تنظیم، هر درخواست ثبت‌شده نیز به این آدرس POST می‌شود |

> نکته: تگ‌های `canonical` به صورت **نسبی** تولید می‌شوند، بنابراین روی هر دامنه‌ای بدون نیاز به rebuild معتبر هستند. نشانی‌های `og:url` / `og:image` و نسخه استاتیک `sitemap.xml` به `SITE_URL` وابسته‌اند؛ سرور، نقشه سایت پویا و صحیح را مستقل از آن ارائه می‌دهد.

نحوه استقرار:

- توصیه‌شده: اجرای `node server.js` پشت یک reverse proxy (nginx / پلتفرم میزبانی). سرور، مسیرهای تمیز (`/courses/skin-facial/`) و API فرم‌ها را با هم ارائه می‌دهد.
- اگر فقط فایل‌های `public/` را روی یک هاست استاتیک قرار دهید، صفحات و تصاویر کار می‌کنند اما **فرم‌ها نیازمند سرور Node هستند** (endpointهای `/api/...`).

## ۴. موجودی و مدیریت تصاویر

- **۲۷ عکس اصلی** در `image/` و **۱ لوگوی رسمی** در `logo/` بررسی و دسته‌بندی شدند: تابلو/پوستر رسمی، پذیرش، سالن انتظار، کلاس‌ها، کارگاه کمک‌های اولیه، مدل‌های آناتومی، اتاق‌های درمانی، محصولات مراقبت پوست و دکوراسیون.
- تمام عکس‌ها به **WebP** با دو اندازه (`@1600px` و `-sm@720px`) بهینه و با `loading="lazy"`, `decoding="async"`, `srcset`/`sizes` و ابعاد مشخص ارائه شده‌اند. حجم کل تصاویر وب حدود ۴٫۵ مگابایت است.
- لوگوی رسمی (`public/assets/images/raouf-logo.jpg`) **کپی بایت‌به‌بایت** فایل `logo/` است و با `object-fit: contain` و تناسب ۱:۱ در هدر، هیرو، فوتی و بخش هویت بصری استفاده شده؛ نه بازسازی شده، نه کشیده شده.
- عکس‌های «عمل فیشیال»، «محیط داروخانه/نسخه» و «اجرای ماساژ» در فایل‌های تأمین‌شده وجود نداشتند. طبق مجوز پرامپت، **۶ تصویر جایگزین حرفه‌ای** تولید شد (هیچ لوگو یا گواهی‌نامه جعلی تولید نشد):

| فایل | کاربرد |
| --- | --- |
| `hero-academy.jpg` | تصویر هیرو صفحه اصلی |
| `course-facial.jpg` | کارت و هیرو دوره پاکسازی و فیشیال |
| `course-pharmacy.jpg` | کارت و هیرو دوره تکنسین داروخانه |
| `course-pharmacy-2.jpg` | بخش عملی/گالری دوره داروخانه |
| `course-massage.jpg` | کارت و هیرو دوره ماساژ |
| `course-massage-2.jpg` | گالری دوره ماساژ |

دوره فوریت‌های پزشکی از **عکس‌های واقعی تأمین‌شده** (مانکن CPR، مدل آناتومی، کارگاه) استفاده می‌کند. هیچ تصویری به دوره نامرتبط اختصاص داده نشده است. گالری فقط عکس‌های واقعی آموزشگاه را نمایش می‌دهد.

## ۶. فرم‌ها و بک‌اند (عملکرد واقعی، نه شبیه‌سازی)

`POST /api/registrations` و `POST /api/contact`:

1. اعتبارسنجی **سمت کاربر و سمت سرور**: نام، شماره موبایل ایران (پشتیبانی ارقام فارسی/عربی، `+98` و `0098`)، دوره معتبر، موضوع، رایانامه اختیاری و محدودیت طول پیام.
2. محافظت: توکن **CSRF** به روش double-submit cookie، فیلد **honeypot**، **محدودیت نرخ** (۸ درخواست / ۱۵ دقیقه / IP) و **جلوگیری از ارسال تکراری** (همان شماره + دوره/موضوع طی ۱۰ دقیقه، حتی پس از راه‌اندازی مجدد سرور).
3. ذخیره امن: رکوردها به صورت append-only در `data/registrations.jsonl` و `data/contacts.jsonl` با دسترسی `0600` نوشته می‌شوند؛ IP خام ذخیره نمی‌شود (فقط هش کوتاه).
4. **پیام موفقیت فقط پس از نوشته شدن واقعی روی دیسک** نمایش داده می‌شود و شماره پیگیری (`REG-...` / `MSG-...`) برمی‌گردد. در صورت خطای ذخیره، خطا به کاربر اعلام می‌شود.

تحویل به مدیر:

- همیشه: رکوردها در فایل‌های بالا (پایگاه داده محلی) ذخیره می‌شوند.
- `ADMIN_TOKEN` را تنظیم کنید تا بتوانید با `GET /api/admin/submissions` و header `X-Admin-Token` رکوردها را دریافت کنید. بدون توکن، endpoint بسته است (۴۰۳).
- `ADMIN_WEBHOOK_URL` را تنظیم کنید تا هر رکورد به سرویس/ایمیل‌گیت‌وی مدیرتان نیز ارسال شود. اگر تنظیم نشده باشد، هیچ ادعای ارسال ایمیلی مطرح نمی‌شود.

مثال:

```bash
ADMIN_TOKEN=my-secret ADMIN_WEBHOOK_URL=https://hooks.example.com/raouf node server.js
curl -H 'X-Admin-Token: my-secret' http://localhost:3000/api/admin/submissions
```

سایر قابلیت‌ها: منوی کشویی دسکتاپ و منوی drawer موبایل، آکاردئون FAQ، فیلتر و لایت‌باکس گالری (کیبورد، focus)، دکمه بازگشت به بالا، نوار ثابت تماس موبایل، لینک `tel:` و اینستاگرام، و انیمیشن‌های اسکرول با احترام به `prefers-reduced-motion`.

## ۷. دسترسی‌پذیری، سئو و کارایی

- `<html lang="fa" dir="rtl">`، فونت **Vazirmatn** متغیر به صورت محلی، تایپوگرافی صحیح فارسی با نیم‌فاصله، سلسله‌مراتب heading و کنتراست مناسب.
- نشانه‌گذاری معنایی (`header`, `main`, `nav`, `section`, `footer`, `figure`, `dialog`)، `alt` برای تمام تصاویر، `aria-expanded` / `aria-controls` / `aria-pressed` /skip-link.
- عنوان و توضیح متای **منحصربه‌فرد** برای هر صفحه، canonical، Open Graph، JSON-LD (`EducationalOrganization` / `Course`)، `robots.txt` و `sitemap.xml`.
- فشرده‌سازی gzip برای متن، کش assets، lazy loading، ابعاد مشخص تصاویر، بدون درخواست خارجی و بدون کتابخانه سنگین.

## ۸. تست و تضمین کیفیت

```bash
npm test            # ۷ گروه تست HTTP/HTML/API (node:test، سرور جداگانه روی پورت ۴۳۹۹)
npm run qa:screens  # ۲۰ اسکرین‌شات + ۱۵ تست تعاملی در Chromium واقعی
```

`npm run qa:screens` به ابزارهای QA-only نیاز دارد که **عمداً در مخزن قرار نگرفته‌اند** (`.work/` در `.gitignore` است):

```bash
mkdir -p .work/qa && cd .work/qa
npm init -y >/dev/null 2>&1 || true
npm i @sparticuz/chromium@153 puppeteer-core@25
cd ../..
npm run qa:screens
```

خروجی: `screenshots/desktop/*.png` و `screenshots/mobile/*.png` (۲۰ فایل)، به علاوه `.work/qa-report.json`. جزئیات کامل نتایج در **[TEST_REPORT.md](./TEST_REPORT.md)** آمده است.

برای ساخت مجدد تصاویر بهینه از روی فایل‌های اصلی، ImageMagick لازم است (`convert`)؛ خود سایت و `npm run build` به آن وابسته نیستند چون نسخه‌های بهینه در `public/assets/images/` از پیش موجود و کامیت شده‌اند.
